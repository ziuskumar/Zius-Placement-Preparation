# 📋 Functional vs Non-Functional Requirements

---

# 📖 Introduction

Before designing any software system, the first step is understanding **what the system should do** and **how well it should perform**.

These requirements are divided into two categories:

- Functional Requirements (FR)
- Non-Functional Requirements (NFR)

Every successful system design begins by identifying both types of requirements.

---

# 📌 Definition

### Functional Requirements (FR)

Functional Requirements describe **what the system should do**.

They define the features and functionalities expected from the application.

---

### Non-Functional Requirements (NFR)

Non-Functional Requirements describe **how the system should perform**.

They define the quality attributes of the system such as performance, scalability, reliability, and security.

---

# ❓ Why Are Requirements Important?

Without clear requirements:

- ❌ Wrong system architecture
- ❌ Poor scalability
- ❌ Missing features
- ❌ Performance issues
- ❌ Higher development cost

Requirements help engineers design the right system from the beginning.

---

# ⚙️ Functional Requirements

Functional requirements describe the business logic of the application.

Examples:

- User Registration
- User Login
- Upload Photos
- Like Posts
- Comment on Posts
- Send Messages
- Search Products
- Place Orders

These answer the question:

> **What should the system do?**

---

# ⚙️ Non-Functional Requirements

Non-functional requirements describe the quality of the system.

Examples:

- High Availability
- Scalability
- Security
- Reliability
- Performance
- Fault Tolerance
- Low Latency
- High Throughput

These answer the question:

> **How should the system behave?**

---

# 📊 Functional vs Non-Functional Requirements

| Functional Requirements | Non-Functional Requirements |
|--------------------------|-----------------------------|
| Describe features | Describe quality |
| What the system does | How the system performs |
| Business logic | Performance metrics |
| Login | Response Time |
| Search | Scalability |
| Payment | Availability |
| Upload File | Security |

# ⚠️ Common Mistakes

❌ Mixing Functional and Non-Functional Requirements.

❌ Ignoring scalability.

❌ Focusing only on features.

❌ Forgetting security requirements.

❌ Designing before gathering requirements.

# 🔥 Interview Questions

### ❓ What are Functional Requirements?

Functional Requirements define the features and operations the system must perform.

---

### ❓ What are Non-Functional Requirements?

Non-Functional Requirements define how the system should perform in terms of quality attributes like performance, security, and scalability.

---

### ❓ Give examples of Functional Requirements.

- Login
- Registration
- Search
- Payment
- Upload File

---

### ❓ Give examples of Non-Functional Requirements.

- Scalability
- Availability
- Security
- Reliability
- Low Latency

---

### ❓ Which comes first in System Design?

Requirement gathering always comes before architecture and implementation.

---

# 💡 Best Practices

- Gather complete requirements before designing.
- Separate Functional and Non-Functional Requirements.
- Consider future scalability.
- Document assumptions.
- Clarify ambiguous requirements with stakeholders.
